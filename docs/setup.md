# Setup and API notes

## Supabase database requirements

The team's demo project already has these tables. A new project needs equivalent tables and defaults before intake can save a quote. This describes the application's contract; it is not a migration of the live project.

### `quotes`

| Column | Expected type / behavior |
| --- | --- |
| `id` | UUID primary key, generated by default |
| `join_token` | Text, required |
| `status` | Text: `extracting`, `clarifying`, `quoted`, `approved`, or `error` |
| `email_text` | Text, required |
| `spec` | JSONB containing the ten fields in `lib/types.ts` |
| `missing` | Field-name array; the API expects a JSON array |
| `options` | Nullable JSONB array of price options |
| `version` | Integer, defaults to `0`; increments on changes |
| `intake_at` | Timestamp with timezone |
| `quoted_at` | Nullable timestamp with timezone |
| `approved_at` | Nullable timestamp with timezone |

Each specification field stores `value`, `status`, and `source`, with optional `evidence` and `note`. The saved fixture demonstrates the expected shape.

### `quote_events`

| Column | Expected type / behavior |
| --- | --- |
| `id` | Generated primary key |
| `quote_id` | Quote UUID; references `quotes.id` |
| `call_id` | Nullable text; extraction events do not supply it |
| `kind` | Text accepting `extracted`, `answer`, `rejected`, and `unsupported` |
| `payload` | JSONB; tool arguments, result, and processing metadata |

Require uniqueness on **`(quote_id, call_id)`** for non-null call IDs. The answers route uses it to reserve calls and prevent duplicate application. Index `quote_id` for history queries. Price requests use `payload.result.priceRequest`, not a separate table or `quotes` column. The enriched quote response includes `priceRequests` for display.

Server operations use the secret key. The browser Realtime listener also needs the `quotes` table in the Realtime publication and suitable read policies. Do not add a blanket public read policy to private buyer data just to enable Realtime: the backend's two-second refresh works without it. Production requires authenticated, vendor-scoped access; the MVP does not provide that yet.

`npm run db:check` verifies table connectivity only. `npm run test:integration` checks actual writes, reads, retries, and approval with disposable test data.

## API routes

| Method and route | Purpose / input |
| --- | --- |
| `POST /api/quotes` | FormData: `emailText`, PDF `pdf` (up to 4 MB), optional `useSaved=1` for the bundled saved extraction |
| `GET /api/quotes/:id` | Quote plus price-request history; response uses `no-store` |
| `POST /api/quotes/:id/voice-token` | `{ joinToken }`; validates buyer link and creates a short-lived Live token |
| `POST /api/quotes/:id/answers` | `{ joinToken, callId, tool, args }`; validates and applies a tool request |
| `POST /api/quotes/:id/approve` | `{ joinToken, version }`; approves only the current provisional quote |
| `POST /api/quotes/:id/reset` | Demo reset; clears buyer fields/history and rotates the join token |

Reset removes existing event history and invalidates the old QR link. It is a demo-only route without employee authentication; don't expose it as a production workflow.

### Gemini tools

- `record_answers`: supported material, integer quantity from 1–5000, and supported finish. Only buyer-stated or explicitly confirmed choices are saved.
- `note_unsupported`: preserve unsupported values as notes; retain previously valid choices.
- `note_price_request`: exact wording plus optional `requestedAmountCents` and `basis` (`total` or `per_part`). Amount and basis must be supplied together; prices and approval are unchanged.

Materials: `AL6061`, `AL7075`, `SS304`. Finishes: `AS_MACHINED`, `ANODIZE_CLEAR`, `ANODIZE_BLACK`. Anodizing is rejected for stainless steel.

## Troubleshooting

- **QR opens the wrong place:** check `NEXT_PUBLIC_APP_URL` and redeploy after changing it. Phone calls need accessible HTTPS; `localhost` works only on the same computer.
- **Microphone unavailable:** allow access on the HTTPS site or choose typed input. Typed mode still uses Live and can reply aloud.
- **Old agent instructions:** end the session and start a new call. Deployed behavior also requires the latest code to be deployed.
- **Quote does not save:** check database connectivity, table defaults, and the unique quote/call constraint with the integration test.
- **Extraction fails:** check model availability and the server API key. Use saved extraction only for the bundled drawing and disclose that fallback.
- **Missing dimensions:** intake stops when drawing-required fields are missing; the buyer agent must not invent them.
- **Realtime unavailable:** polling should still refresh every two seconds. Check publication and scoped policies before claiming Realtime is active.
